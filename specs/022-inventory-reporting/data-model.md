# Data Models: Inventory Query, Reporting, & Administrative Jobs

This document defines the database schemas, field types, indexes, and relationships required for the Phase 9 features.

## 1. Entity Definitions

### 1.1 WarehouseLock (Updated Schema)

Represents the locked state of a warehouse during a stocktake count.

| Field Name | Type | Nullable | Attributes | Description |
|---|---|---|---|---|
| `id` | `String` | No | `@id @default(uuid())` | Primary key |
| `warehouseId` | `String` | No | `@unique` | Foreign key to `Warehouse` |
| `isActive` | `Boolean` | No | `@default(true)` | Active status blocking write operations |
| `status` | `LockStatus` | No | `@default(ACTIVE)` | `ACTIVE`, `STALE`, or `RELEASED` |
| `sessionId` | `String` | No | | Reference to the current `StocktakeSession` |
| `expiresAt` | `DateTime` | No | | Expiration timestamp (typically 72 hours from lock start) |
| `lockedAt` | `DateTime` | No | `@default(now())` | Creation timestamp |
| `lockedById` | `String` | No | | Foreign key to `User` who initiated the lock |

**Prisma Enum:**
```prisma
enum LockStatus {
  ACTIVE
  STALE
  RELEASED
}
```

**Indexes:**
- `@@index([isActive, expiresAt])` - Used by the background cleanup job to quickly identify expired active locks.

### 1.2 NotificationLog (New Entity)

Represents role-based alerts generated by document workflow events.

| Field Name | Type | Nullable | Attributes | Description |
|---|---|---|---|---|
| `id` | `String` | No | `@id @default(uuid())` | Primary key |
| `targetRole` | `Role` | No | | Role of users who should receive this notification |
| `warehouseId` | `String` | Yes | | Optional warehouse scope limit |
| `message` | `String` | No | | UI display text |
| `isRead` | `Boolean` | No | `@default(false)` | Flag indicating if a user has read/dismissed this alert |
| `createdAt` | `DateTime` | No | `@default(now())` | Timestamp when the alert was created |
| `documentType` | `DocumentType` | Yes | | `PR`, `PO`, `GRN`, `TRANSFER`, etc. |
| `documentId` | `String` | Yes | | ID of the triggering document |

**Indexes:**
- `@@index([targetRole, isRead])` - Used by the frontend polling endpoint to fetch active unread notifications.
- `@@index([warehouseId])` - Filter notifications to the authorized scope.

### 1.3 AuditLog (Existing/Updated Entity)

Immutable historical log for auditing critical mutations.

| Field Name | Type | Nullable | Attributes | Description |
|---|---|---|---|---|
| `id` | `String` | No | `@id @default(uuid())` | Primary key |
| `beforeStateJson`| `Json` | Yes | | JSON snapshot before mutation |
| `afterStateJson` | `Json` | Yes | | JSON snapshot after mutation |
| `performedByUserId`| `String`| No | | User ID from JWT |
| `performedByRole`| `Role` | No | | User role from JWT |
| `warehouseId` | `String` | Yes | | Active scope warehouse |
| `branchId` | `String` | Yes | | Active scope branch |
| `createdAt` | `DateTime` | No | `@default(now())` | Creation timestamp |

**Indexes:**
- `@@index([warehouseId, branchId])` - Scoped lookup filters.
- `@@index([createdAt])` - Sorting index for paginated audits.

## 2. Validation & Domain Constraints

1. **Lock State Transition constraints**:
   - `ACTIVE` -> `STALE` (triggered only by system background job when `expiresAt < NOW()`).
   - `ACTIVE` / `STALE` -> `RELEASED` (triggered only by manual unlock endpoint or successful Stocktake POST).
2. **Notification logs are read-only**:
   - Only the `isRead` field can be updated via the read endpoints. `UPDATE` or `DELETE` on other attributes is prohibited.
3. **Audit logs are fully read-only**:
   - `AuditLog` records are strictly append-only. No updates or deletions are permitted on this table.
