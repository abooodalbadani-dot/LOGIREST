## Summary

LogiRest is an Arabic-first (RTL) internal web application for multi-branch restaurant inventory and procurement management. The frontend must provide 116 screens covering 8 operational modules: Foundation, Design System, Shared Components, Procurement (PR→PO→GRN), Operations (Issue/Transfer/Adjustment/Stocktake), Master Data, Inventory Views, Notifications, Reports, and Administration.

The technical approach is: **Next.js 16 App Router + React 19 + TanStack Query v5** for RSC-driven data fetching; **React Hook Form + Zod v4** for forms; **next-intl v4** for Arabic-first RTL/LTR; and the **"Operational Nocturne"** Tailwind v4 design system. All API calls are currently mocked; the architecture anticipates a real backend with the same contract surface defined in `contracts/api.md`.

**Target Platform**: Modern web browsers (Chromium, WebKit); responsive down to 390px for scan mode
**Project Type**: Web application (internal)
**Performance Goals**: Scan re-focus ≤100ms; 10-item issue flow ≤60 seconds; document list load p95 ≤800ms
**Constraints**: RTL-first (ar default); dark mode only (Operational Nocturne); zero hard-coded strings; posted docs are read-only
**Scale/Scope**: 116 screens, 8 epics, 8-week delivery schedule

### Key Decisions Made

| Area | Decision |
|------|----------|
| Next.js version | 16.2.4 App Router; async `searchParams`/`cookies` required |
| React version | 19.2.4; no `forwardRef`; Actions API usable for forms |
| TanStack Query | v5 only: `gcTime` (not `cacheTime`); no `useQuery` callbacks |
| Zod | v4: use `z.string().min(1)` not `.nonempty()` |
| next-intl | v4: `getTranslations()` async in RSC; `useTranslations()` in client only |
| Tailwind | v4: CSS `@theme {}` for tokens; no `tailwind.config.js` token object |
| FX Rate | Internal table only (clarification Q1) |
| Camera scanning | UI hooks only, USB wedge is primary (clarification Q2) |
| RBAC data scope | Branch/Warehouse scoped; API enforces; JWT claims inform UI filtering |
| Stocktake lock | Block POST only; draft preparation allowed (clarification Q4) |

## Phase 1: Design & Contracts

**Status**: ✅ Complete

### Data Model
**Output**: `specs/001-logirest-frontend-ui/data-model.md`

Key entities:
- `AuthUser` (role + scopes array)
- `Branch`, `Warehouse`, `Item`, `Lot`, `Supplier`, `Currency`, `FXRate`, `Department`
- `BaseDocument` + type-specific extends: `GRN`, `PurchaseRequest`, `PurchaseOrder`, `StockIssue`, `Transfer`, `Adjustment`
- `StocktakeSession` + `StocktakeCount`
- `WarehouseLockState` (for `useWarehouseLock` hook)
- `AuditLogEntry`, `NotificationTemplate`, `EmailOutboxEntry`
- `PaginatedResponse<T>`, `ApiError`

**State Transitions**:
- Documents: `DRAFT → SUBMITTED → APPROVED → POSTED` (immutable after post)
- Stocktake: `OPEN → COUNTING → REVIEW → POSTED` (warehouse lock held throughout)

### API Contracts
**Output**: `specs/001-logirest-frontend-ui/contracts/api.md`

Contract covers: Auth, Master Data, Inventory (balance/lots/ledger/lock), Procurement (PR/PO/GRN), Operations (Issue/Transfer/Adjustment), Stocktake, Notifications, Administration.

**Key error codes** for UI handling:
- `WAREHOUSE_LOCKED` (409) → surface `LockBanner`, disable POST
- `DOCUMENT_POSTED` (409) → show read-only overlay
- `FX_RATE_REQUIRED` (422) → surface `FXRateCapture` step in confirmation dialog
- `EXPIRED_LOT_BLOCKED` (422) → prompt for override reason (ADMIN only)

### UI Contracts (Component Interface Requirements)

| Component | Key Props Contract |
|-----------|-------------------|
| `ScanInput` | `onScan(barcode, qty, uom)`, `onError(barcode)`, `disabled` |
| `FEFOLotAllocator` | `lots: Lot[]`, `requestedQty`, `onAllocate(allocations[])`, `userRole` |
| `PostConfirmDialog` | `title`, `description`, `warningText`, `requiresTextConfirmation?`, `onConfirm: async fn` |
| `LockBanner` | `warehouseId`, `lockState: WarehouseLockState` |
| `DataTable<T>` | `columns`, `data`, `isLoading`, `pagination`, `onExport`, `emptyState` |
