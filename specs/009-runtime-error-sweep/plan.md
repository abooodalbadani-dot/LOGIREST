## Summary
The goal is to eliminate all frontend runtime errors, specifically hydration mismatches, React key warnings, and memory leaks (state updates on unmounted components). The approach involves a production-build audit, standardized use of `AbortController` in `apiClient`, and verification of the global conflict resolution layer.

## Technical Context

**Language/Version**: TypeScript / Next.js 15+ (App Router)
**Primary Dependencies**: React 19, TanStack Query, Zod.
**Storage**: N/A (Client-side stability audit)
**Testing**: Manual Production Audit + Concurrency Simulation.
**Target Platform**: Browser (Web)
**Project Type**: web-application
**Performance Goals**: 0 console warnings; < 100ms UI response to conflict alerts.
**Constraints**: Zero `suppressHydrationWarning` usage except for documented exceptions.
**Scale/Scope**: Universal (All 50+ routes in `apps/web/src/app`).
